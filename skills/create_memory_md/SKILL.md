# create_memory_md

> 根据解析好的"记忆细节 + 主观描述"，生成 `{memoryId}.md` 文档。
> 文档即记忆——md 是回忆记忆的唯一完整载体，向量库只索引其摘要。

## 触发场景

- echo-core 保存记忆后异步调用 `/memory/parse`，解析完成后再生成 md。
- 单个源文件删除后，需要从 md 中移除对应片段、重算摘要、覆盖回写。
- 用户在前端编辑 md 内容后，回写到对象存储（覆盖同名 key）。

## 输入

- `topic`：记忆主题（时间+地点+人物+事件）
- `subjectiveDesc`：用户对本次记忆的主观描述（≤1000 字，可空）
- `details`：来自各源文件的解析细节，结构 `[{fileName, fileType, detail}]`
- `existingMd`：可选，已有 md 的原文（删除/更新场景，用于增量修改）

## 输出

- 一个完整 markdown 字符串。约定结构：

```markdown
# {topic}

## 摘要
（一段 ≤200 字的概要；包含时间/地点/人物/事件要点）

## 元数据
- 时间: YYYY-MM-DD（从 topic/subjectiveDesc 提取，若不明则 `未知`）
- 地点: ...（同上）
- 人物: 用户, Agent, ...
- 情感标签: [温馨, 怀旧, ...]
- 强度: 0.85（1.0 为最高）
- 来源: [file1.jpg, file2.mp3, ...]

## 记忆细节
### 片段 1 [来源: file1.jpg]
（来自该文件解析出的细节描述）

### 片段 2 [来源: file2.mp3]
（音频转写 / 视频关键帧描述）

## 记忆主观描述
（用户的原话描述，可为空）
```

## 生成流程

1. 调用 LLM（默认用小模型节省成本，长细节时升级到大模型），输入：
   - system：上述输出结构 + 规则（"只归纳不改写、保留细节来源、摘要 ≤200 字"）
   - user：`topic + subjectiveDesc + details[].detail` 拼接
2. 校验输出结构：缺失 `# / ## 摘要 / ## 元数据 / ## 记忆细节 / ## 记忆主观描述` 五大节时，按模板补齐。
3. 返回字符串。

## 设计约束

- **绝不动回忆记忆的隔离原则**：本 skill 只生成 / 更新文档，绝不直接修改 `EchoRecall` 向量。
- **幂等**：相同输入产生相同 md 文本，便于断点重跑。
- **可读性优先**：人写人看的文档，不是给机器进一步处理的结构化数据。
- **元数据兜底**：无法确定的字段写 `未知` 或留空，绝不编造。
